# サーバーの更新のしかた

## 自動の更新 (tools/install-auto-update.sh を入れた後)
サーバーが 5 分ごとに GitHub の作業ブランチを確かめ、新しい版があって**自動テスト (GitHub Actions) が全部通っていたら**、`tools/update.sh` で自分で更新します。
マージやプッシュをすると、テストが終わってから 10 分ほどでサーバーに入ります。誰も操作しなくて構いません。

- 入れる (最初に 1 回だけ。サーバーで): `cd ~/SHOWROOM-log-in-System && git pull && bash tools/install-auto-update.sh`
- 記録を見る: `journalctl -u showroom-auto-update --since today`
- 一時停止: `touch ~/SHOWROOM-log-in-System/.no-auto-update` (このファイルを消すと再開)
- 止める: `sudo systemctl disable --now showroom-auto-update.timer`
- テストが失敗した版は入れません。テストがまだ終わっていない版は、終わるまで待ちます
- 急ぐ時や、自動の更新を止めている時は、下の方法で更新します

作業ブランチ `claude/showroom-login-persistence-gfdxzo` に変更を入れた (マージした) あと、サーバーに反映するには、利用者に次の方法を案内します。

## いつもの方法 (Mac のデスクトップの「サーバーを更新する.command」)
1. Mac のデスクトップにある **「サーバーを更新する.command」をダブルクリック**する
2. ウィンドウが開き、次の順に進む (数分かかることがある。英語の文字が流れても待つ)
   1. `== 1. 最新を取ります` … 入った変更の一覧
   2. `== 2. 版の番号を書きます` … 版の番号 (例: `9a4e0a7`)
   3. `== 3. 作り直して起動し直します` … 視聴は 1 分ほど途切れる
   4. `== 4. 起動したか確かめます` … `管理画面が動いています`
3. 最後に `更新が終わりました。` と出たら終わり。何かキーを押すと閉じる

中身はサーバーで `tools/update.sh` を実行するだけです (git pull → `showroom_keeper/VERSION` に版の番号を書く → `sudo docker compose up -d --build` → 管理画面が動いているか確かめる)。

## 更新できたかの確かめ方
- 管理画面の「収集」の、上の枠のいちばん下に `動いている版: 9a4e0a7 (…) ・ GitHub の最新: 9a4e0a7 … ・ 最新です` と出る
- サーバーが古い時は、管理画面の上に「新しい版があります」と出る (GitHub の最新はサーバーが 1 時間に 1 回調べる)
- 「動いている版: 不明」と出る時は、`tools/update.sh` を使わずに更新している (版の番号が残っていない)

## デスクトップにファイルが無い時 (最初の 1 回)
Mac のターミナルに次の 1 行を貼って実行すると、デスクトップに置かれる。
```
curl -fsSL -o ~/Desktop/サーバーを更新する.command "https://raw.githubusercontent.com/mutsu-6/SHOWROOM-log-in-System/claude/showroom-login-persistence-gfdxzo/tools/%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC%E3%82%92%E6%9B%B4%E6%96%B0%E3%81%99%E3%82%8B.command" && chmod +x ~/Desktop/サーバーを更新する.command && echo "できました"
```
「開発元が未確認のため開けません」と出たら、右クリック →「開く」→「開く」。

## サーバーで直接更新する時
```
cd ~/SHOWROOM-log-in-System && git pull && bash tools/update.sh
```

## 案内する時の決まり
- 利用者への案内は「デスクトップの『サーバーを更新する.command』をダブルクリック」にする。前の方法 (`git pull && sudo docker compose up -d --build`) は、版の番号が残らないので案内しない
- `.env` を変える必要がある変更は、何を書くか (例: `SHOWROOM_XXX=true`) と、書いたあとに「サーバーを更新する.command」で起動し直すことを案内する。`.env` は root の持ち物なので、サーバーで `sudo nano ~/SHOWROOM-log-in-System/.env` で開く
- 更新の途中で「途中で失敗しました」と出たら、そのウィンドウの写真をもらって原因を見る。管理画面にパスワードがある時の 401 は、動いている印として扱っている (`tools/update.sh`)
- `tools/update.sh`・`tools/サーバーを更新する.command` を変えたら、偽の `sudo`・`docker`・`curl` で手順が通るか確かめる
