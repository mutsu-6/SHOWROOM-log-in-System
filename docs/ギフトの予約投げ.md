# ギフトの予約投げ (時間指定でギフトを送る)

2026-11-05 に利用者 (M) の「作れ」で作った。プログラムは `showroom_keeper/gift_plan.py`、画面は管理画面の「ライブ」→「予約投げ」。

## 使い方
1. 「ライブ」→「予約投げ」で、ルームの URL を入れて「ギフトを読む」
2. ギフト・個数・送る時刻 (日本時間。`2026-11-05 23:59:58.5` のように 0.1 秒まで) を選び、「内容を確かめる」
3. 出てきた内容 (ルーム・ギフト・個数・時刻・使う SG) を見て「予約する」。予約は、送る前ならいつでも取り消せる
4. 結果は同じ画面の表に出る。送り始めた時刻が予定から何ミリ秒ずれたか・返事まで何ミリ秒かかったかも出る

## 状態
| 状態 | 意味 |
| --- | --- |
| 予約 | 時刻を待っている |
| 送信中 | 送る直前〜返事を待っている |
| 送った | SHOWROOM が受け付けた |
| 失敗 | SHOWROOM が断った (送られていない) |
| 不明 | 返事が無い・途中で止まった。**送り直さない**。送れたかは SHOWROOM のギフトの履歴で確かめる |
| 見送り | 配信していない・予定より遅れた・上限を超えた・止まっていた間の予約だった。送っていない |
| 練習 | `SHOWROOM_GIFT_SEND` が off なので、時刻まで待って送らなかった |
| 取り消し | 画面で取り消した |

## 守っていること
- 二重に送らない: 送る前に「送信中」を残し、止まったら「不明」にして送り直さない。返事が分からない時も送り直さない
- 送りすぎない: 有料は 1 回と 1 日 (日本時間) の上限の中だけ。既定は 0 で、有料は予約できない。送る直前にも上限を確かめ直す
- 画面で合計の SG を見せ、その数を送り返さないと予約できない (`confirm_sg`)
- 予定より `SHOWROOM_GIFT_LATE_LIMIT` 秒 (既定 2 秒) 遅れたら送らない
- 視聴を止めない: 問い合わせとファイルの読み書きは、すべて別のスレッド。視聴のブラウザは使わない (ミッションと同じく Cookie を借りる)
- 収集の順番待ち (`research.THROTTLE`) には並ばない (締め切りに遅れるため)。1 件の予約で問い合わせは 3 回 (配信の状態・CSRF トークン・送信)。準備は送る 15 秒前

## 設定 (.env)
| 項目 | 既定 | 意味 |
| --- | --- | --- |
| `SHOWROOM_GIFT_SEND` | off | on で本当に送る。off は練習 |
| `SHOWROOM_GIFT_PAID_MAX` | 0 | 1 回の予約の有料の上限 (SG)。0 なら有料は予約できない |
| `SHOWROOM_GIFT_PAID_DAILY_MAX` | 0 | 1 日の有料の上限 (SG)。予約した分 + 送った分 + 不明の分 |
| `SHOWROOM_GIFT_LATE_LIMIT` | 2 | 予定よりこの秒数より遅れたら送らない |
| `SHOWROOM_GIFT_FREE_PATH` | `/api/live/gifting_free` | 無料ギフトの送り先 (**推定**) |
| `SHOWROOM_GIFT_PAID_PATH` | `/api/live/gifting_point_use` | 有料ギフトの送り先 (**推定**) |

## まだ確かめていないこと (2026-11-05)
- **送り先と送る項目**: 作った所 (開発の箱) から SHOWROOM につながらないため、配信ページが送る宛先を見られなかった。
  `gift_id`・`live_id`・`num`・`is_delay`・`csrf_token` をフォームで送る形は推定。サーバーで確かめてから `SHOWROOM_GIFT_SEND` を on にする
- **「送った」の見分け**: SHOWROOM の返事の形が分からないので、HTTP 200 で `error`・`errors` が無ければ「送った」としている
- **締め切りに何秒前なら間に合うか**: 終わり際は SHOWROOM 側の反映が遅れる (公式)。無料の星で、終わり際に送った時刻と、ギフトの記録・最終結果を比べて測る
- 時計: サーバーの時計 (Google Cloud の時刻合わせ) を使う。SHOWROOM の時計とのずれは測っていない
