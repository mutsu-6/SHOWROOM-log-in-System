# Cursor への依頼: ブロック分けのイベントを SHOWROOM がどう返すかを確かめる (2026-11-11、Claude Code から)

M さんが「イベントのページに、ブロックごとの表示がない」と言った (2026-11-10・11)。直す前に、SHOWROOM がブロックをどう返しているかを知りたい。
手元 (クラウド) からは SHOWROOM につながらず、写しも読めないので、Cursor にお願いします。

**読むだけ**。写しは Mac のもの (読み取り専用で開く)。サーバーでは動かさない。ギフター・ルームの名前と ID は報告に書かないでください (イベント番号は書いてよい)。
SHOWROOM への問い合わせは、下の 4・5 の合わせて 5 回までにしてください。結果は `docs/報告/Cursorの作業_<日付>.md` に。

## 今の作り (Claude Code が調べたこと)

- イベントの一覧 (`/api/event/search`) の `event_block_label` を `event_info.block` に入れ、イベントのページに「ブロック: (名前)」の札を出しているだけ
- 参加ルーム (`/api/event/room_list?event_id=&p=`) は、ブロックを指定せずに読んでいる。順位・必要ポイント・接戦は、イベント全体で出している
- ブロックが 1 つのイベントの中に入っていて、`rank` がブロックの中の順位なら、`event_analysis._final_points` (102〜106 行目) が順位を 1, 2, 3… と振り直すので、必要ポイントがずれる (推測)
- ブロックごとに別のイベント (`parent_id` が同じ) なら、順位は正しいが、「前の回」のくらべにほかのブロックが混ざるおそれ (推測)

## 確かめてほしいこと

1. `event_info.block` に値が入っているイベントの数と、全部のイベントの数。`block` の値の種類を多い順に 20 個 (値と件数)
   (ブロック分けでないイベントにも値が入っているかを知りたい)
2. `block` に値があるイベントのうち、`room_events` で同じ `event_id` の中に同じ `rank` が 2 回以上あるイベントの数と、あるイベントの番号を 3 つ
   ```sql
   SELECT re.event_id, re.rank, COUNT(*) n FROM room_events re JOIN event_info i USING(event_id)
   WHERE i.block IS NOT NULL AND i.block != '' AND re.rank IS NOT NULL GROUP BY re.event_id, re.rank HAVING n > 1;
   ```
3. `block` に値があるイベントで、`parent_id` が同じほかのイベントがあるか。あれば 1 組だけ、イベント番号・名前・`block` を並べて
4. `block` に値がある開催中のイベントを 1 つ選んで、SHOWROOM のイベントのページ (`/event/<key>`) の HTML に `block_id=` が出てくるか。出てくれば、その値をいくつか
5. 同じイベントで、次を 1 回ずつ読んで、返ってきた JSON の上の階層の項目名と、`list` などの 1 件目の項目名を全部
   - `/api/event/room_list?event_id=<番号>&p=1` (1 件目に `block_id` のような項目があるか、`rank` がブロックの中の順位か)
   - `/api/event/block_ranking?event_id=<番号>&block_id=<4 の値>` (あるかどうか分からない。404 ならそう書いてください)
   - 4 で `block_id` が見つかれば `/api/event/room_list?event_id=<番号>&block_id=<値>&p=1` (ブロックで絞れるか)

## このあと

結果を見て、Claude Code が、イベントのページにブロックごとの順位・必要ポイントを出し、前の回のくらべを同じブロックどうしにする。
集め方を変える必要があれば (ブロックごとに読む)、問い合わせの数がどれだけ増えるかを先に M さんに伝える。
