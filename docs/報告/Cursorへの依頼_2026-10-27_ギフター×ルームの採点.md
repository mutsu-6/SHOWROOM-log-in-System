## 何をくらべるか

今の採点 (`backtest.py`) は人ごとで、答えは「次の 30 日の、どれか 1 イベント × 1 ルームの最大」。**どのルームに出すかは採点していない**。
新しい採点は、ルームがイベントに出た 1 回ごとに、そのルームの前からのギフター (365 日に載った人) が、出すか・何 pt 出すかを当てる。

- 正解に使う回: 貢献ランキングを、終わったあとに読んである・推測の名前の行が無い・1 人以上。載っていない人は、100 人に届かない回だけ 0。
  100 人の回は「100 位の外」で量は分からない (0 にしない)
- 開発の期間 (既定 2026-04〜06) と確かめる期間 (既定 2026-07・08) を分ける。**決めるのは確かめる期間の結果で**
- どれも「遡及の比較」で、ルームがそのイベントに出ることは分かっているとした (予定既知仮定。Codex の 15.1)

## 動かし方

```
python -m showroom_keeper.backtest_pair <写しのあるフォルダ> --rooms 2000 --out backtest-pair-2000.json
```

1. まず `--rooms 2000` (ルームを 2,000 部屋だけ選ぶ) で動かし、かかった時間と、メモリの最大 (`/usr/bin/time -l` の maximum resident set size) を書いてください
   (作ったデータでは、21 万件で 24 秒・メモリ 64MB ほど。1 件 0.1 ミリ秒・300 バイトほどなので、500 万件なら 8 分・1.5GB の見込み。推測)
2. 2,000 部屋で 10 分以内・メモリ 2GB 以内なら、`--rooms` を外して全部で 1 回動かしてください (ケースは数百万件になる見込み。推測)
3. 画面の最後に出る 5 行 (出てくるか・出てきた時の量・次のイベントの量・ルームの中の並び・ルームの上の 10 人) を、dev と check の両方、そのまま貼ってください。
   JSON の `periods.check.all` の `cases`・`listed`・`true_zero`・`outside_top100`・`newcomers`・`listed_all`・`label_dropped`・`band`・`by_history`・`confirmed_only` も

## Claude Code が見たいこと (答えは Claude Code が読む。Cursor は数字だけで大丈夫)

- 出てくるか: 分母から取れなかった回を外した割合 (`rate180`) が、今の出動率の数え方 (`rate180_old`) と何も考えない予測 (`naive_last`) に勝つか
- 次のイベントの量: 候補 (`med3_rate180` など) の MAE が、何も考えない予測 (`naive_last`・`naive_90`) より小さいか
- 新顔 (前からの人ではない、載った人) の割合。大きいほど、前からの人だけの予測では足りない
- 100 位の外 (`outside_top100`) の割合。大きいほど、大きいルームでは量の答え合わせができない
