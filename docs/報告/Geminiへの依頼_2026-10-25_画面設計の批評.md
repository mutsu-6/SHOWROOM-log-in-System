## 1. 何をしてほしいか

SHOWROOM Analytics の管理画面 (`showroom_keeper/admin.html`) が、**イベントの作戦を決める人にとって読みやすく・迷わず使えるか**を批評してください。
褒めるより、困る所を具体的に見つけることを優先してください。

見る観点:

1. **読みやすさ**: 数字・単位・期間・「見えていない (未収集・枠の外)」と「0」の区別が、ひと目で分かるか。説明の文が長すぎないか
2. **並びと配置**: 各ページで、いちばん大事なもの (戦い方を決める材料) が上にあるか。同じ情報が何か所にも分かれていないか。メニュー 9 個の分け方は自然か
3. **名前**: 言葉の意味が、説明を読まずに分かるか。同じものが場所によって違う名前になっていないか (下の 3 章)
4. **スマホとパソコン**: スマホの幅で、表・ヒートマップ・カードが読めるか。パソコンで情報が詰まりすぎていないか
5. **ページどうしのそろい方**: 表の形・並べ替え・CSV・期間の選び方・注意書き・色の意味 (緑・赤・青) が、ページをまたいでそろっているか
6. **戦い方につながるか**: イベントの最中に「どのルームが・いつ・どれだけ来そうか」「相手にまだ余力があるか」を決める時、どのページのどこを見ればよいかが分かるか。
   数字を並べただけで、何を決めればよいか分からない所はどこか

## 4. 守ること

- **画面をまとめて作り直す案は出さない** (M の決定)。今ある機能はすべて残し、並び・名前・図・説明を段階的に変える。
  提案には、決定案の作る順番 (① 正しさの小さい直し → ② 欠測の印 → ③ 名前 → ④ 条件比較 → ⑤ ページごとの並びと図 → ⑥ メニューと URL → ⑦ 採点はサーバーの外) の**どの段に入るか**を書く
- **機能を消す・弱める・集めるデータを減らす案は出さない** (今は試験段階で、できることを試す方針)。規約や個人情報についての注意も書かない (M は分かっている)
- **サーバーを重くする・ページを遅くする案は出さない** (サーバーはメモリ 2GB)。SHOWROOM への問い合わせを増やす案も出さない。
  重くなるかもしれない案には「重さは Cursor に測ってもらう必要あり」と書く
- 決定案で M が決めたこと (表は読み込み済みの全行を手元で並べ替える #88 のまま、ルームの構成の分母、ヒートマップの面積など) を変えたい時は、
  理由と根拠を書いて「M に決めてもらうこと」に入れる
- **ファイルは直さない**。見つけたことは、下の報告に書く。直すのは Claude Code (画面の受け持ち)
- **ギフターの名前・ID を報告に書かない** (リポジトリは公開)。写真から例を出す時は「上から 3 番目の人」「あるアイドルのルーム」のように書く
- 本番サーバーにはつながない
