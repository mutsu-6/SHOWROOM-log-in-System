# データ分析戦略部隊

応援しているルームへギフターを誘導する作戦を一緒に考える、相談相手のチームです。
Claude Code の「エージェント」として `.claude/agents/` に置いてあり、このリポジトリで Claude Code を使うと呼び出せます。

## 隊員

| 隊員 | 名前 (呼び出す時) | 得意なこと |
| --- | --- | --- |
| 隊長 (戦略リーダー) | `strategy-lead` | 相談の入り口。作戦案を 2〜3 個出して、おすすめと最初の一歩を決める。必要なら他の隊員の見方をまとめる |
| データ分析担当 | `data-analyst` | 集めたデータから数字を出す (誘導の候補の人数、離れつつある人、ルーム同士の重なり、送る時間帯) |
| イベント担当 | `event-analyst` | 投げ銭バトルの勝ち方 (出るイベントの選び方、何位に何ポイント必要か、ライバルの強さ、勝者の予想) |
| 仕組み担当 | `data-engineer` | 作戦に必要な機能やデータの集め方を考えて作る。サーバー (e2-small) と SHOWROOM の負荷を守る |
| 見張り役 | `risk-advisor` | 規約・負荷・アカウントの安全・ギフターの個人の情報・迷惑にならないかを確かめる |

## 相談のしかた
Claude Code で、次のように頼みます (隊員の名前を入れると、その隊員が答えます)。

```
strategy-lead に相談: 応援ルームを〇〇に決めた。最初の 1 か月で何をすればいいか
data-analyst に聞いて: 離れつつあるギフターは何人いるか
event-analyst に聞いて: 来月の〇〇イベントで 3 位に入るには何ポイント要るか
risk-advisor に確認: 全ルームの収集を続けて大丈夫か
data-engineer に頼む: docs/改善アイデア.md の 1 (ウォッチリスト) を作って
```

迷ったら `strategy-lead` に話しかければ、隊長が他の隊員に振り分けます。

## 相談の時に添えると答えがよくなること
- 応援しているルーム (決まっていれば)
- 期間 (今週・今月・次のイベントまで など)
- 管理画面の「分析」タブの数字や写真 (隊員はサーバーのデータを直接は見られないため)
- 隊員がサーバーで実行するコマンドを出したら、その結果を貼る (データを読むだけのコマンドだけを出すことにしている)

## 決まり (全員に共通)
- 説明は日本語で、分かりやすい言葉で書く
- 誘導は「応援ルームを知ってもらい、楽しんでもらう」形にする。しつこい・だます・なりすますような作戦は出さない
- SHOWROOM への問い合わせを増やす作戦は、見張り役の確認を通す。視聴とログインの維持を、収集より優先する
- ギフターの名前・ID は相談の中で必要な分だけ使い、ファイルやコミットに残さない
- パスワードなどの秘密の情報は書かない

## 定期の見直し (週に 1 回のおすすめ)
1. `risk-advisor`: 収集の状態 (問い合わせの間隔、エラー、ディスクの空き) を確かめる
2. `data-analyst`: 誘導の候補・離れつつある人・伸びている人の数の変化を出す
3. `event-analyst`: 来週のイベントと、応援ルームが出るとよいものを挙げる
4. `strategy-lead`: 来週の作戦を 1 つに決める
